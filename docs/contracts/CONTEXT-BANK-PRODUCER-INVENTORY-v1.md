# Context Bank Producer Inventory v1

> **Status:** CB0.2 inventory baseline / implementation input
> **Date:** 2026-09-01
> **Owner:** Twin AI Core
> **Decision dependency:** [ADR-CB-001](../decisions/ADR-CB-001-CONTEXT-BANK-POINTER-LEDGER.md)
> **Scope:** active producer groups in `bizcity-twin-ai`

This inventory is a routing artifact for CB4 adapters. It records the current
canonical owner and the migration boundary; it does not authorize a producer
to write Context Bank before CB1-CB3 and the relevant runtime probe pass.

## Scope and evidence rules

- Active code only. Paths containing `_archived/`, `_library/`, `vendor/`,
  backup or generated output are excluded.
- A source table/file remains canonical for its own business role. A Context
  Bank row is a pointer/correlation projection and never a payload copy.
- Unknown or migration-incomplete fields are explicitly marked `TBD` or
  `untracked`; they are not inferred from labels, UI state or the current user.
- Account, tenant and identity resolution must happen before Context Bank
  admission. Provider IDs and message content are not safe ledger dimensions.

## Explicit unknowns and gates

| Unknown | Why it blocks CB4 | Required evidence / owner |
|---|---|---|
| Automation run owner identity | `bizcity_automation_runs` does not currently prove a user-owned scope | Add/verify owner contract through R-DCL/R-CR and TwinWeb/automation owners; do not infer admin identity |
| Memory filestore contracts and retention | Current memory SQL paths are migration debt, not a safe Context Bank payload source | Register each role contract, define retention/erasure and add a runtime probe owned by Knowledge/Intent |
| Per-tenant producer rates and peak concurrency | Static estimates cannot justify ledger indexes or worker budgets | CB0.3 fixtures plus bounded runtime counters; owner: each source team |
| Woo guest identity policy | Guest email/customer mapping can become PII leakage or an accidental identity merge | Explicit canonical resolver and two-tenant fixture; owner: Woo/CRM |
| Archive-to-ledger receipt contract | Archive must expose a lock-captured receipt before ledger projection | CB2.3/CB4.2 archive owner and Context Bank ledger owner |

## CB0.2 exit status

The active producer owner map is now recorded, including seven producer groups,
classification and rollback ownership. CB0.2 remains **PARTIAL**, not complete:
producer-wide runtime hooks, rates, two-tenant fixtures, owner approvals and
memory/automation identity gaps remain open. No producer is authorized for CB4
capture solely by appearing in this inventory.
