# BizCity Twin Brain — Workspace Instructions

This is a WordPress plugin (`bizcity-twin-ai`) running on **PHP 7.4**.

## Ultimate Product Direction

**Directive from Johnny Chu - Chu Hoàng Anh, 2026-08-28.** `bizcity-twin-ai`
must remain an **enterprise analytical brain**, not a collection of isolated
chatbots or plugins. Its architecture has three mandatory dimensions:

- **Horizontal:** Channel Gateway connects and normalizes enterprise channels
	and systems such as CRM, POS, inventory, messaging, and other business data.
- **Vertical:** Vertical Brain Modes provide domain capabilities; extensions
	expand them through explicit contracts and reuse the shared brain spine.
- **Knowledge:** Internal documents are built into the Knowledge Graph/Graph
	RAG and provide the evidence layer for extraction, analysis, evaluation, and
	filtering.

The brain may act as the governed intelligence/filter layer that connects MCP
to AI tools. MCP, tools, and extensions must respect the existing identity,
tenant, permission, evidence, and contract boundaries. Core extensions include
Chatbot, GPT/Twin GPT, Profile, Landing Page, Automation, and Notes. They extend
the enterprise brain; they must not create a parallel brain or siloed data path.

Every README, guide, proposal, and implementation must preserve this direction.
Before accepting a change, verify how it strengthens the horizontal gateway,
vertical modes, and KG knowledge layer. A change that fragments enterprise
data, bypasses the Channel Gateway/KG, or breaks extension contracts is out of
direction and must be redesigned before implementation.

## Self-Diagnosing Closed Loop

Treat [PHASE-0-RULE-BRAIN-UNIFICATION.md](./docs/rules/PHASE-0-RULE-BRAIN-UNIFICATION.md) Contract 11 and [R-CLI-CONTRACTS](./docs/rules/PHASE-0-RULE-CLI-CONTRACTS.md) as top-level development gates for every core, framework, module, and plugin change.

- Every new or changed capability needs a canonical Diagnostics probe with Disk/Loader/Runtime evidence, a narrow rerun command or batch, and an actionable `fix_hint` for every `fail` or `warn` result.
- Every `fail` or `warn` result must carry safe rerun metadata for the single probe, owning batch, and `wp bizcity probe`; derive commands from registered IDs only, never from arbitrary shell input.
- Run diagnostics in small fixed batches: `health`, `schema`, `core`, `channel`, `knowledge`, `twinweb`, `external`, or `direct`. One process runs one batch; use `--run-id=<id>` and `--resume=<id>`, then use `--aggregate=<id>` only after required batches complete. Use `--require-complete` for the release gate.
- Never use a recursive full-workspace search as runtime evidence. Static searches must use narrow active roots and exclude `_archived/`, `_library/`, `vendor/`, backups, generated files, and unrelated repositories. Timeout or incomplete search is `deferred/incomplete`, never PASS.
- Do not treat `precondition_skip`, `network_skip`, `admin_required_skip`, `direct_only_skip`, or `budget_deferred` as executed PASS. Use `--require-complete` for release gates.
- CI/nightly coverage uses one shared `run_id` across separate PHP processes for `health`, `schema`, `core`, `channel`, `knowledge`, `twinweb`, and `external`; the first batch may provision and later batches use `--skip-provision`, then `--aggregate=<run_id> --require-complete`. `direct` is explicit-only.

## LocalWP / Production SQL Safety

LocalWP is an optional probe harness, not a requirement to prove self-diagnosing readiness. When LocalWP is used, it must use explicit loopback DB settings from `wp-config-local.php` or `BIZCITY_LOCAL_DB_*`; never guess a port or fall back to production.

- Do not run write SQL, schema repair, installer, migration, `dbDelta()`, cron mutation, or REST mutation against the current production hosting database.
- If the local DB endpoint is not proven to be loopback, stop and report configuration failure.
- Production inspection, when explicitly authorized, is bounded read-only metadata/`SELECT` only.
- Do not create, print, commit, or upload production credentials. The real `wp-config-local.php` remains ignored; use `wp-config-local.php.example` as the template.

## Architecture Quick Summary

- **Shell Engine** (5 steps): Init → Pre-rules → Classify → Memory → Dispatch
- **Smart Classifier** (server-side): 2 modes ONLY — Single | Multi. Emotion = tone, NOT mode.
- **8 Pipeline Blocks**: skill → planner → research → memory → content → tool → reflection → verifier
- **2 Modes**: Single (1 tool → Canvas output) | Multi (N tools pipeline)
- **Canvas**: Studio Panel = single-goal output surface. All creative tools output here. Canvas Adapter = handoff layer (P1: Content Creator, P2: Image + Video).
- **Canvas Adapter gate**: `studio_enabled: true` + `content_tier >= 1` in Tool Registry. Atomic tools (scheduler, gmail) bypass Canvas — inline execute.
- **Memory Lifecycle**: CREATE (Shell 3.5) → SEED → UPDATE (Block 4) → FINALIZE (Block 7)
- **Legacy 5-mode classifier**: DEAD CODE when Shell Engine ON. Do NOT reference MODE_EXECUTION/MODE_AMBIGUOUS.

## Critical Rules

0. **Canvas = Single-Goal Output.** Mọi creative tool (content creator, image, video) output qua Canvas (studio panel). Single-goal là nhánh chính. Canvas Adapter = handoff layer: Intent dispatch → Canvas execute → complete. Xem §5a trong PHASE-0-RULES.md + [PHASE-1.20-CANVAS-ADAPTER.md](./PHASE-1.20-CANVAS-ADAPTER.md).
1. **Shell dispatches, Blocks execute.** Don't put execution logic in Shell.
2. **Tool = Atomic.** No LLM calls, no DB saves, no context awareness inside tools.
3. **Skill = Recipe (Markdown/YAML).** Don't write PHP flows for skills.
4. **DDL must match INSERT/SELECT code** character-by-character.
5. **Every `$wpdb->insert/update` must check `=== false`** and `error_log()`.
6. **Memory Spec lifecycle must close**: CREATE → FINALIZE. Never leave orphaned specs.
7. **Context injection respects token budgets.** Don't inject full knowledge into Classifier.
8. **PHP 7.4 only.** No `match`, no named arguments, no `readonly`, no union types.
9. **`dbDelta()` quirks**: No `IF NOT EXISTS`, no `DEFAULT CURRENT_TIMESTAMP ON UPDATE`.
10. **Every block must drive UI change.** No silent background operations.
11. **Only 2 modes: Single | Multi.** Emotion is tone, NOT a mode. Legacy 5-mode classifier is dead code.
